# ADR 0018: neutral-first design system

Status: accepted.
Implementation: complete.

The starter ships one interface language instead of the shadcn defaults plus two display fonts: a neutral-first palette, Figtree as the single font, one compact type and spacing scale, a component library in `apps/web/components/ds/`, a collapsible shell with route skeletons and a navigation progress bar, toasts, the `/design-system` showcase and the [design system guide](../design-system.md). Adopters start from a coherent, accessible admin and remove nothing to look like a product.

Interface colour is neutral: near-black ink, cool greys, a `#FAFAFA` canvas and white cards with a light border. Surfaces are never tinted; colour appears only as a dot, an icon, a number, text or a thin border. Two colour families keep fixed roles. The AI family is a small violet icon (`--ai-ink`) and a thin violet stroke (`--ai-mark`); the violet → pink gradient is reserved for the bars of one hero chart per page. The semantic family is positive, negative, attention and neutral, with green restricted to positive numbers: a positive state draws a neutral circled check, so the same hue never means two things. Categorical series use `--chart-1..5` and user-created identities use `--accent-1..5`; every new series colour must pass the palette validator (luminance band, colour-blindness separation, contrast) in both themes.

Figtree replaces Manrope and Newsreader, self-hosted through `next/font/google`, with tabular figures on every number. The compact scale is the only one: 13 px body, 12 px tables, 16 to 18 px titles, 24 px KPIs, controls at least 32 px tall; its tokens live in `@theme` and `:root`, with no density attribute or saved preference. `cn()` registers the scale, the named spacings, the card radius and the shadows in tailwind-merge so a caller's class replaces the token's instead of fighting it in the cascade.

Charts are hand-written SVG with tokens, a tooltip, keyboard focus and an equivalent table; no charting dependency. Toasts come from `react-hot-toast` 2.6.1 (pinned) wrapped by `components/ds/toast.tsx`, mounted once in the root layout, for confirmations only; decisions go in an `AlertCard`. Loading follows one pattern: skeletons only on the first load, `RefreshRegion` when a filter or period changes the query key, a route skeleton in every `loading.tsx`, the top progress bar on every navigation and `pending` on every mutation button.

The showcase at `/design-system` is an authenticated route listed under the Developer section of the sidebar. It renders every component with fictional, product-agnostic data and is the visual reference for review; adopters may delete the route and the sidebar item without touching the components.

Text generated by the interface follows the writing rules in the guide: a fact and a date in the title, numbers instead of adjectives, an action verb on the button, short sentences, and colour never as the only cue. Strings and comments are in English, formatters default to `en-US` and `USD` through `components/ds/format.ts`, and any other locale or currency is a parameter.

This decision changes `apps/web` only. Laravel, the contracts and the generated client are unchanged, and the existing routes keep their behaviour. The shadcn/ui components stay on the Base UI primitive set; the design system builds on them instead of replacing them.
